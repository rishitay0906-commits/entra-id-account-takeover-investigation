# Cloudora CLD-0001 — Synthetic Identity Compromise Dataset

Synthetic Microsoft Entra ID sign-in and audit logs for the Cloudora incident
response exercise. Generated data only. No real people, tenants, or IP addresses
belonging to any organisation.

Generated by `generate_cloudora_logs.py` with a fixed RNG seed, so the dataset is
byte-for-byte reproducible.

| File | Rows | Target table |

## Scenario

Cloudora is a 150-person B2B HR software company headquartered in London. The
dataset covers 8 days, from 2026-07-26 00:00 UTC to 2026-08-02 12:00 UTC, all
timestamps in UTC.

At 08:55 on 2026-08-02 the IT admin flags a sign-in on the CEO's account
(`daniel.reeve@cloudora.io`) that occurred at 03:12 from an unexpected location.
Your job is to confirm or dismiss the compromise, establish the full timeline,
identify persistence, and determine whether any other account was affected.

The dataset deliberately contains benign anomalies that will fire on a naive
detection query. Distinguishing them from the real activity is part of the
exercise.

### Result codes present

`0` success · `50126` invalid credentials · `50074` strong auth required ·
`50076` MFA required by policy · `50140` keep-me-signed-in interrupt ·
`50053` account locked · `53003` blocked by Conditional Access

## Ingestion into Azure Data Explorer

1. Create the free cluster at `dataexplorer.azure.com` → **My cluster** → **Create cluster**.
2. Create a database named `cloudora`.
3. Right-click the database → **Get data** → **Local file**.
4. Table name `CloudoraSignIn_CL`. In the schema preview, set `TimeGenerated`
   to `datetime` and **set `ResultType` to `string`**. Entra result codes are all
   digits, so type inference will guess `long` and every
   `where ResultType == "50126"` will silently return zero rows.
5. Repeat for `cloudora_audit_logs.csv` into `CloudoraAudit_CL`.

### Verification queries

```kql
CloudoraSignIn_CL | count
// expect 1479

CloudoraSignIn_CL | where ResultType == "50126" | count
// expect 123 — if this returns 0, ResultType ingested as a number

CloudoraAudit_CL | count
// expect 51

CloudoraSignIn_CL
| summarize StartTime = min(TimeGenerated), EndTime = max(TimeGenerated)
// Azure Data Explorer has no global time picker, so scope every query yourself
```
